# Contributing to QuakeC Studio

Thanks for helping. These guidelines apply to every repository in the
[quakecstudio](https://github.com/quakecstudio) organization unless the
repository has its own `CONTRIBUTING.md`.

## Before you start

- Search the existing issues first. If nothing matches, open one describing
  the bug or the change you want, and wait for a reply before starting on a
  large change.
- Security problems go through [SECURITY.md](SECURITY.md), not public issues.

## Pull requests

- Branch from `main` and keep each pull request to one logical change.
- Write commit messages in the imperative mood ("Add hover docs for builtins"),
  with a subject of 72 characters or fewer.
- Make sure the repository's checks pass locally before you open the pull
  request. Each repository's README says how to run them.
- Describe what the change does and how you tested it.

Pull requests merge through a merge queue as a single squashed commit, using
the pull request title as the commit subject.

By contributing, you agree that your contribution is licensed under the
repository's license, and you agree to follow the
[Code of Conduct](CODE_OF_CONDUCT.md).
